# System design

The workbench preserves a recoverable modeling decision: intent, exact situation,
observations, constrained intervention, independent judgment and retained method.
The modeling owner controls this system directly. There is no inference middle
layer, prompt transport or alternate model executor.

## Linked abstractions

1. **Private authority and state.** The character workspace selects identity,
   accepted guides, current checkpoint, owner, scope and unresolved question.
   Source-bound facts and user edits outrank stale plans and galleries.
2. **Decision episode.** Intent, hypotheses, evidence, operations and separate
   character/method dispositions form one recoverable record. Historical baseline
   state does not replace current native observation.
3. **Operating session and task graph.** A qualified catalog declares inputs,
   outputs, methods and prerequisites. Explicit owner choices route useful work.
   Fixed dependencies run in code. Reviews and experience link back to the episode.
4. **Reusable capabilities.** Parameterized methods, array preparation, semantic
   inspection, guide fitting, preservation, candidate pipelines, jobs and retention
   expose meaningful operations without embedding a particular character.
5. **Native adapter and immutable evidence.** One owner executes with atomic
   expected-state checks, consumed constraints and durable receipts. Actual
   returned observations support review; uncertain effects cannot be repeated.

Python, CLI and MCP expose the same service. The package/skill boundary is generic;
assets, private history, scene anatomy and adapter configuration stay external.
Initialization creates a complete independent workspace and portable skill.

## Modeling and retention

Every appearance change uses applicable registered guides, depth and corresponding
sections during construction. Preservation protects evaluated outcomes across the
affected motion, not only frozen controls or endpoints. If a local correction
cannot coexist with those outcomes, identify the structural conflict, solve the
connected transition and restore the guide-defined result within qualified bounds.

Review matched appearance early against the guide and earlier useful baseline.
Broader verification answers concrete concerns after a useful candidate. Retain
overall gains without ratcheting through regressions. Save/reopen, numerical
realization, visual judgment, operator retention and user acceptance remain
different evidence classes. User rejection invalidates dependent targets.

## Execution and recovery

Direct operations retain native guards. Sessions additionally enforce task
contracts, preservation omissions, exact evidence consumption and review gates.
Single eligible operations run directly; multiple choices need explicit owner
priority or a local selector. No missing condition is silently inferred true.

Queues journal before effects and save returns before report validation. Recovery
restores an exact completed result or reconciles uncertainty against original
receipts, never retries blindly. When a capability raised after its inner effect,
the evidence-backed reconciliation of the original operation settles the task as
failed so the same session can continue with a corrected revision. Precondition
guards run before the first write, so a refusal leaves no partial record.
Historical selections, provider accounting and checkpoints stay readable without
the retired transport implementation. Fresh direct sessions require current
explicitly bound catalogs.

## Accretive methods and portability

Retain supported techniques, failure mechanisms, applicability, limits and
counterexamples through existing experience APIs. Relevant evidence enters later
observations with missing coverage visible. Promote generic methods and synthetic
regressions into the package; keep exact character artifacts private.

Complete tools, references, setup and the isolated job runner ship together.
Recreate environments and plugin configuration per machine. Qualify local Blender
and scene adapters independently of package tests. CI checks synthetic behavior
and clean installation on Windows, macOS and Linux. Neither portability nor
execution correctness establishes cross-character artistic quality.

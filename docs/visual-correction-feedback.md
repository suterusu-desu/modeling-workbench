# Useful workflow and visual correction feedback

When a user corrects what an edit was meant to improve, replacing an explanation
or presenting only candidate codes can hide the misunderstanding. This delivery
keeps exact target words, marked source regions, interpretation/proposal revisions
and comparisons together, with version-bound feedback and retrievable corrections.

The primary route is a finite useful modeling cycle, grounded in observed local
guide/depth/section fitting and coherent motion construction. Its method drafts
explain scope and limits. A successful diagnosis is labelled separately from a
successful repair; experiments and known failure patterns are not default recipes.

The manually started loopback UI uses the existing Store/Ledger/ModelingService.
It pins images, supports independent regional revisions, qualifies local reference
roles without clearing global rejection, labels baseline LEFT/trial RIGHT, and
compares recorded inspection/baseline/trial descriptors and annotations. Exact
camera/native authenticity remains a source assertion requiring separate evidence.

Typing feedback binds its draft to the displayed comparison. Changed selections
cannot silently retarget it; concurrent/stale submissions refuse and preserve form
text. Corrected interpretations retain their predecessors. Agreement, technical
verification, visual usefulness, retention and result acceptance remain independent.

The working view foregrounds current evidence. Other images and provenance stay
expandable; board/image archives are recoverable presentation events. All bytes,
referenced images, target revisions, comparisons and decisions remain accessible.
No native work, mandatory modeling approval layer or runtime adoption is added.

Validation at delivery: six focused contracts, the full suite (726 tests, 10
skipped), wheel/tools clean installs, source inventory/privacy checks, and an
actual headless Edge browser workflow (31 checks) covering create/mark/interpret/
compare/correct/reopen, concurrent/stale/result-switched drafts, explicit facts,
unknown/mismatched views, archive/restore, private saved evidence and mobile layout.
Browser receipts and character screenshots stay outside public source. This proves
the delivered communication workflow, not artistic improvement or cross-character
native qualification. No foreground/native Computer Use interaction is claimed.

# A useful modeling correction cycle

The workbench exists to improve a character and preserve the methods that helped.
Start with the current visible problem and accepted appearance, then use the
smallest relevant construction and evidence tools. A tool inventory, successful
test suite or accumulated candidate count is not the modeling outcome.

## What the development evidence supports

| Practice | Observed result | Applicability and limit |
|---|---|---|
| Registered guide overlap, depth and corresponding sections during shape fitting | Early owner-recognized likeness gains; later anatomy-consistent supported fits | Useful for supported static form. Guides can contain noise, incompatible anatomy or missing depth; qualify regions instead of copying whole outputs. |
| Construction before motion fitting, shared timing and carried attachments | A connected rebuilt mechanism produced an owner-recognized motion improvement; later compact baking and export round-trip were verified | Adapt to the current anatomy. This does not prescribe one hinge, travel ratio, threshold or shape count for all characters. |
| Scoped surface smoothing that preserves accepted boundaries | An owner-accepted local rest/closed-surface change in the development case | A historical local success, not a general solution to later bumps, corner crowding or strain. New surface edits still need supported spatial constraints and visible proof. |
| Source/dirty-state, binding/realization checks, isolated trials and independent reopen | Caught stale sources, omitted control influence and edits that failed to reach displayed geometry; preserved recoverable work | These establish their safety/correctness contracts. They cannot establish likeness or human acceptance. |
| A controlled matched visible-defect diagnosis | Separated ordinary normal recalculation from sampled geometry/deformation in a later surface problem | Diagnosis succeeded; the requested complete skin repair remained unresolved at this evidence snapshot. Do not present it as a demonstrated smoothing method. |

This is a bounded synthesis of the original development case, not cross-character
validation or a causal ranking of every package feature. Full source receipts,
owner wording and character assets remain in the private project's evidence map.
The public package contains the general procedures and anonymous regressions.

## One finite cycle

1. **Clarify the appearance.** Read the current project page and the user's latest
   words. Mark the actual inspection image; name what should change and what
   should remain. Accepted artwork governs identity. The last owner-approved
   result is a comparison baseline, even when a later editable source is needed.
   Use [visual correction feedback](visual-feedback.md) to keep the wording,
   interpretation, references and corrections durable and understandable.
2. **Choose the appropriate construction.** For static shape, use registered
   support/depth/corresponding sections during the edit. For motion, study and
   build a coherent mechanism from the accepted rest before fitting its few
   parameters. See [construction first](build-the-mechanism-first.md),
   [guides and display](guide-and-show.md) and [motion paths](motion-paths.md).
   Reuse useful evidence; generate a new guide only for a named missing constraint.
3. **Resolve only consequential uncertainty.** A diagnostic must answer a question
   that changes the next edit. Trace visible defects to the actual evaluated
   surfaces and distinguish geometry, normals, shading and occlusion where needed.
   See [construction diagnostics](construction-diagnostics.md). A rejected guide
   may still supply qualified local appearance evidence; keep its rejected depth
   and excluded geometry separate from that useful role.
4. **Build and compare a recoverable result.** The sole native owner reconciles
   live/source/dirty state, builds an isolated trial, and compares enlarged and
   whole-character views at matched conditions, with guide overlap where useful.
   Review joins, attachments and affected closing/reopening/in-betweens. Use
   [trial, reopen, retain](trial-reopen-retain.md), relevant declared checks and
   the actual native result. Numeric scores can reveal failure; they do not
   approve appearance or establish success on an untested character.
5. **Keep the supported gain and its limits.** Independently reopen consequential
   candidates, save useful outcomes and preserve the previous checkpoint. Record
   technical verification, visual usefulness, retention and owner acceptance
   separately. Correct misunderstandings visibly. Keep source-bound failures
   accessible; put incidental artifacts in the optional recoverable presentation
   archive instead of letting them dominate the next target.

## What stays outside the recommended route

Accumulated independent per-pose fields, a guide-generation reflex, retaining
against only the previous candidate, preserving defective coordinates merely
because they exist, and treating an improved contour as a skin-surface repair
have caused failures. Keep their receipts and any scoped exceptions, but do not
present them as the default modeling recipe.

New local guide transfer, surface fairing and untested mechanisms remain
experiments until their scoped evidence supports them. Existing diagnostics and
recovery tools serve the modeling question; no additional orchestration or
approval layer is required merely to use this workflow. The feedback UI records
communication evidence and method drafts. Native execution continues through
the configured workbench adapter and existing owner.

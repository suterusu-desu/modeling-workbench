# Validated response reuse and package transfer

`record_dependencies` pins recorded geometry/construction, topology, pose, bindings, targets and optional view separately. `register_semantic_graph` and `validate_semantics` retain actual role evidence. A new coordinate snapshot does not make an invalid anatomical mapping valid.

`register_response(dependencies, semantic_validation, spec, arrays_path, evidence)` implements the scalar `sparse_pointwise_v1` adapter. NPZ arrays are `data`, `indices`, `indptr`, `shape` (CSR), `baseline_input`, `baseline_output`, `output_ids`. Optional `limit`, `selected`, `epsilon` implement the explicit smooth-min support branch. Declare `kind` as `exact_linear`, `exact_piecewise`, `local_derivative`, or `approximate`; no approximation becomes exact by fitting one sample. Specify input/output domains, actual output object/axis/frame, units, a finite maximum delta and all geometry/construction/pose/guide/binding/target dependency domains. `influence` includes known region, missing region, boundary, and controls for which the supplied ancestry evidence establishes complete influence.

`predict_response` refuses changed dependencies and out-of-range controls. Supply guide/depth/section constraints with the prediction. Its computed affected output rows do not prove that an incomplete sparse export captures every influenced neighbor. A partial prediction remains useful recorded analysis; it cannot authorize a native proposal. `propose_change(response_model={"prediction": id}, ...)` requires the prediction's exact baseline and complete scoped influence. Advanced scripts/constraints are pinned as exact bytes before execution.

`compare_prediction` compares owned native coordinates with the prediction and preserves worst residuals and actual whole/close/angle/guide-depth/motion/appearance inspection. Numerical agreement and an improved metric never approve a crease. The current comparison adapter supports recorded world coordinates; local-frame responses need an explicit validated transform/rebinding, not a silently assumed frame. Native verification remains with the sole Blender owner. Save/reopen requirements remain proportional to the retained candidate and cannot be replaced by predicted coordinates.

Registration checks the declared baseline against actual recorded native world coordinates. An internally consistent matrix and invented baseline cannot pass as exact native evidence. Historical native-local registration requires the exact converted ancestry asset, adapter evidence, source state, face geometry and Y axis; set `adapter_evidence` to the adapter record and output frame to `native local`.

`adapt_ancestry_response` converts the retained scoped subdivision/ocular export and measures both its original native samples. It preserves the source-state/topology/modifier/support fingerprint and nonlinear branch. Historical 950-output ancestry is not current T13 validation or full-character influence. Binding it to another source state is refused. Use the existing advanced native procedure if it covers more than this scalar adapter, retaining exact inputs and results through the same episode.

`check_reuse(record, before, after, domains)` reports recorded dependency equality. Reuse unchanged geometry across a changed camera, while refreshing the matching view. This does not establish live freshness or current semantic validity. A response always checks all its own required domains.

`schedule_ordered_motion` retains source timestamps and distinct closing/reopening sample identities with exact rational times and independent cycles. It exposes missing samples per cycle. It creates a frame map, not new geometry or a replacement video. The older nearest-control/reversed-cache replay remains explicitly historical. The source-specific scheduling lesson is supported by the retained T13 outcome; it does not prove all arbitrary intervals can be shown at a fixed output frame rate.

`promote_procedure` requires explicit supported method judgments and preserves applicability, limits, counterexamples and exact executables. One supported episode yields a local procedure; reusable level requires demonstrated reuse across distinct episodes. Promoted records enter retrieval. Promotion alone does not prove installed skill or operator adoption. Preserve unresolved artistic judgment alongside a supported method.

`evidence_manifest(episode)` traverses immutable records/assets and explicit private locators, hashes and missing coverage. `export_package(output_path, episode, include_evidence=False)` produces a verified portable ZIP of the core, procedures, skill, character binding, captured authority and evidence manifest. Embedding private episode assets is explicit; the default declares their availability rather than pretending they shipped. Existing packages are preserved. A transferred package starts with native control unconfigured. Bind the actual destination character and adapter before native use; other-character modeling quality remains unproven.

`package_readiness` checks actual evidence hashes/availability and runtime. `verify_installation(cache_root)` verifies source-to-cache launch/skill bytes and runs that installed launch in a fresh process to inspect its actual MCP schema. This is stronger than a caller-provided version string, but still does not prove an existing Codex task picked up the schema. Use a fresh task to read the installed skill and exercise the bound episode without the previous conversation; retain misses and fix them before claiming transfer.

For a relocated export, use `package_readiness(manifest_path="/destination/evidence-manifest.json")`; embedded paths resolve against that manifest while original locators remain provenance. Complete embedded exports preserve operation intents/results, native-effect receipts, resolution records and leases as well as workflow pointers and immutable records. A missing declared asset is reported, not treated as available analysis.

Rejection and rollback differ. The existing native rollback needs the exact trial `after.expected_state`; subsequent review pose/view changes can invalidate it. Do not relax this guard or blindly reset review state. A supported owner-controlled continuation can start a new guarded transaction from verified actual live content toward an explicit comparison baseline, retaining actual-before and comparison arrays and both trials. Record static rejection separately from saved/applied working state, preserve later user edits and current pose/view intent, and retrieve the L63 recovery procedure. Dependency-specific content-verified rollback remains unimplemented.

The workspace binding declares `adapters.ancestry_ocular_v1.inputs` with all three named arguments (`npz_path`, `schema_path`, `verification_path`). Resolve those locators against the explicit workspace. All three source files are declared by the evidence manifest; missing private input stays unsupported. Native control is unnecessary for this retained-array example.

For the complete exported example, use the explicit workspace service and resolve the declared arguments: `inputs = {name: str(work.workspace / path) for name, path in work.binding["adapters"]["ancestry_ocular_v1"]["inputs"].items()}`; then `work.adapt_ancestry_response(**inputs)`. This creates local retained analysis in that workspace/store; use an isolated extracted copy for an evaluation. It does not call Blender or certify a current coupled XYZ deformation.

# Diagnose the control family before another fit

Use `inspect_control_coverage(case_path, expected_state)` when a new target is fitted with an inherited control selection, or native realization matches the prediction but connected shape still fails. It retains an offline report and exact inputs through the ordinary service/journal. CLI and MCP expose the same operation. It does not contact Blender or select new controls automatically.

Keep four questions separate: whether all outputs of selected controls were measured; whether all ancestors of current targets were found; whether allowed controls have useful qualified response under protection; and whether the realized shape is good. Forward accuracy answers the first question only. Structural ancestry can pass through a zero current derivative or a downstream clamp; it does not establish controllability.

The version-1 JSON case contains `question`, `state`, `outputs`, `controls`, `ancestry`, `targets`, `selected_controls`, `allowed_controls`, and `exclusions`. `expected_state` must match the recorded `source_state_id`, `pose`, `frame`, `units`, and `dependency_fingerprint`. This is a recorded-state check; native freshness still belongs to the owner.

`outputs` and `controls` are ordered lists of `{id, meaning}` with exact native/coordinate meanings. IDs are unique strings within each domain. `targets` selects output IDs; selected and allowed lists select control IDs, with allowed a subset of selected. Every selected-but-disallowed control needs `{control, reason, interpretation, evidence}` in `exclusions`. Interpretations are `protected`, `trial_restriction`, or `unresolved`. Omitted controls can also carry exclusions. A historical rectangular work window is not automatically permanent user intent.

`ancestry` repeats the state fields, has `kind: "structural_dependency"`, evidence, a hash-pinned `arrays: {path, sha256}`, and `coverage: {universe_complete, complete_for_outputs, missing}`. Arrays are NPZ CSR `shape=(output_count, control_count)`, `indptr`, `indices`, `data`. Every stored data value must be one: edges express known structural dependencies, not derivative magnitudes. Convert an exact sparse dependency operator only with a justified zero/nonzero interpretation; never threshold a measured derivative into an exhaustive ancestry claim. Inspect all relevant upstream paths and downstream mechanisms separately. A matrix restricted to old controls must say `universe_complete: false`, even if it includes all outputs of those controls.

The compact result reports omissions, targets with no allowed ancestor, and incomplete coverage. Its `reads` expand exact target identities, parent lists, exclusion reasons and pinned input evidence. Known omissions remain visible even when coverage is incomplete. `selected_covers_declared_target_ancestry` means only that declared, evidenced ancestry is covered. The report always leaves controllability unestablished and native readiness false.

Declare `target_scope: {status, basis, evidence, missing}` separately. Status is `unknown`, `declared_subset` or `complete_for_question`; a completeness claim requires a basis, evidence and an explicit empty missing list. Omission defaults to unknown. Reverse completeness for listed targets does not establish that the target list covers the guide-supported surface. If correspondence was screened only inside an old influence patch, first inventory the broader supported target domain before merely expanding its controls.

Use the report to classify missing paths and inspect why freedom was excluded. Newly found ancestors may reach protected geometry outside the old output patch: expand their complete forward support before judging admissibility. When justified, prepare a revised control family with fresh complete forward influence and qualified coupled response; use `analyze_repair` for the supplied finite fit/preservation problem. Existing guide/depth, boundary, neighboring-layer, motion, independent reopen and appearance checks still apply. More controls, lower residuals, or a complete ancestry map alone do not justify another generation or prove smoothness. Retain the prior failed field as a counterexample.

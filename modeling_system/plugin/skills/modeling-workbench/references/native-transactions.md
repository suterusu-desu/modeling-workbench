# Isolated native transactions

Use these helpers for a closed raw-mesh experiment or a measured library append in an owner-controlled disposable/background Blender process. Existing qualified workspace adapters remain available for rigs, guides and character operations outside this helper's declared scope. A new generic install does not switch the active native owner. Match installed module bytes to the selected worker and use its isolated-profile runner.

For qualified character adapters with dependent parts, diagnose preservation through the recorded attachment relationship as well as raw displacement: fixed anchors can have moving support frames. Use the [baseline and expected-frame checks](construction-diagnostics.md#distinguish-expected-attachment-motion-from-residual-error) before interpreting a dependent-coordinate difference. This does not expand the raw writer's supported content or relax exact native fingerprints, save boundaries or later-edit rollback refusals. Artistic permission and a mechanically explained response remain separate.

## Prepare, execute, inspect, retain

1. `prepare_mesh_batch(case_path)` retains a version-1 case containing `question`, `object`, `mesh`, `steps` and optional `aliases`. It returns a bounded plan summary and a `read_record` expansion. It neither inspects Blender nor grants native readiness.
2. The native owner creates `native_mesh_batch.SaveBoundary(bpy, owner, fingerprint)`. `fingerprint()` must hash the actual complete declared native content at native precision, including protected objects and datablocks. Pin its implementation/dependencies and state its coverage. A rounded coordinate summary is insufficient. The helper requires background Blender and one boundary owner/session.
3. Inspect the actual raw mesh using `read_mesh`. Supply explicit POINT INT identity and optional FACE INT identity attribute names. Call `execute_batch(boundary, object_name, steps, output_dir, expected, aliases=..., identity_attribute=..., face_identity_attribute=...)` once with `expected=boundary.stamp()` from the reviewed baseline. The entire sequence compiles before native writes; checkpoint saves occur only after compilation. An output directory must be new.
4. Retain the returned receipt and its hash. `inspect_native_transaction(receipt_path, expected_sha256)` verifies historical artifacts without contacting Blender or writing records. It exposes the pending step and completed steps after failure. Reopening an old receipt does not refresh the live state.
5. Record each successful step's `lineage_case` through `record_topology_lineage`, compose matching revisions and remap selectors through the existing service. A step's produced ancestry is exact for its declared vertex domain; FACE IDs retain surviving face ownership. No edge ancestry, rig transfer, proximity inference or anatomical correspondence is claimed.
6. Independently reopen retained candidates and partial states before judging preservation. Use the worker completion contract for durable preflight, checkpoint verification and final inventory. Evidence of native mechanics remains distinct from appearance approval.

Both preparation results expose `reads` as a named map (`reads.plan`) and `detail` as the same single operation/arguments descriptor. Expand only the needed plan; the descriptor requests an 8,000-character read window and large fields return further bounded expansions. Older retained 0.2.11 results used a single descriptor directly in `reads`. Do not rewrite them: `bounded_reads.normalize_reads(result['reads'], default_name='plan')` accepts either shape and returns an independent named map while preserving its exact arguments/budget. This helper only normalizes shape; it neither executes a descriptor nor establishes permission or native freshness. New consumers should use `detail` for one plan or iterate the normalized/named `reads` map.

The mesh schema contains canonical nonnegative decimal-string `ids` representable by native INT, exact finite float32 `co`, vertex-ID `faces`, `face_materials`, `face_smooth`, and optional `face_ids`. Supported steps are `translate`, `split_vertex` with an explicit proper subset of incident face indices and fresh `new_id`, `merge_vertices` with explicit survivor and mean position, and `delete_vertices`. Selections are explicit IDs or an alias. Alias ancestry follows each step. Partial ancestry merges refuse the whole plan under default `strict`; `any` or `all` must be explicit. A stale alias or invalid later step cannot cause earlier writes. Plans have bounded element, loop, step and aggregate snapshot limits.

The raw writer preserves supported geometry, material slots, per-face material/smooth flags and declared IDs. It refuses shared mesh ownership, shape keys, modifiers, weights, UVs, animation, unsupported attributes, hidden geometry, loose edges and explicit sharp/seam edges. Selection is a transient editing state, not a preservation claim. Use a qualified existing adapter for richer content; do not strip it to make this writer accept a character.

## Save and recovery boundary

`SaveBoundary` tracks owner, session, exact native hash, original saved file bytes/path, dirty flag and save events. `rollback_batch(boundary, receipt_path)` accepts only a fully applied transaction whose current stamp exactly matches its original `after` token. A one-ULP edit, a later same-path save even with unchanged native content, or a new session refuses rollback. The operation saves an abandoned-state copy before opening the original rollback copy. It does not overwrite the user's original file.

Every completed step has its own original receipt and ancestry. A failure before or after a write is `partial_or_uncertain`; save its partial state and preserve the original rollback copy. Such a receipt never authorizes automatic rollback. The owner compares exact saved/current state in a separately identified recovery, preserves any later work and chooses a new scoped action. Do not replay the batch to reconstruct missing metadata. A final save handler changing geometry also leaves the transaction partial: successful file writing does not prove the saved candidate equals current geometry.

These are cooperative trusted-owner concurrency guards, not a sandbox for arbitrary native scripts or malicious save handlers. The pinned fingerprint defines the measurable preservation scope.

## Library closure and explicit names

Measure the source in an unchanged isolated source-file process with `native_library.describe(bpy, roots, library_reference, fingerprint_id, adapter_reference)`. It pins the original library and external files, measures actual native ID dependencies from the declared roots and hashes each ID with references normalized to source identity. The bundled `library_content.fingerprint_id` supports mesh/empty objects, raw meshes, collections, material-owned embedded Principled/Output shader trees, and object drivers including their native default curve points, handles, interpolation, modifiers and explicit ID targets. Source probes exposed shader trees and identity driver curves created by native defaults; do not strip those defaults to manufacture support. Shape keys, actions/NLA, wider shader graphs and richer modifiers/constraints need separately qualified content adapters. Embedded IDs are fingerprinted through their actual owners, not assumed to be independently appendable from a collection name. External Python driver namespace or implicit context dependencies require separate qualification.

`prepare_library_import(manifest_path, existing, namespace, limits)` exposes the offline plan. Existing destination IDs are `[RNA_type, name]` pairs; actual execution recomputes them. The namespace prefixes every declared ID. Collision checks use the underlying data collection, including the shared node-group namespace. Resource ceilings count the full dependency closure once; caller limits may only tighten ceilings. Missing, unreachable or unsupported dependencies refuse preflight. There is no overwrite, silent reuse or global orphan purge.

The destination owner calls `native_library.append(boundary, manifest, namespace, output_dir, expected, fingerprint_id, fingerprint_host, host_adapter_reference, limits=None)`. Both content adapters are source-pinned. `fingerprint_host(original_ids)` must hash all original content and relationships within that original ID set, allowing only the explicitly added root memberships. Include orphan/shared/protected data relevant to the destination; unsupported coverage must refuse before append. Native append verifies returned ID identity, names, complete dependency edges, per-ID source content, original host preservation and the final saved candidate. Parent, shared mesh/material and driver target relationships are measured instead of inferred from names. Unexpected extra IDs or post-append differences preserve a partial receipt/checkpoint; they are never reported as a refusal with no effects. Successful import uses the same guarded rollback helper.

Blender can create one transient `Library` provenance ID during local append. The qualified case has the exact pinned source filepath, no parent, no `user_map` owners or linked payload, `users == 1`, `use_extra_user == True` and no fake user. It disappears naturally on independent saved-file reopen; Mesh/Material weak source references persist. Retain this narrowly checked class in `runtime_library_provenance`, and hash the exact durable weak-reference filepath/ID names as saved content. A full-content adapter must distinguish that runtime-only record when comparing save/reopen states. Do not silently omit original host libraries or other Library IDs, purge the transient ID, or normalize arbitrary metadata differences. Payload ID/resource counts and this separately bounded provenance record are distinct. Preserve the original failed invocation that exposed any mismatch.

Blender's [library load interface](https://docs.blender.org/api/5.2/bpy.types.BlendDataLibraries.html) and [native ID dependency/file maps](https://docs.blender.org/api/5.2/bpy.types.BlendData.html) supply the native observations. Actual supported behavior must be qualified on the selected Blender build with independent saved-state reopens.

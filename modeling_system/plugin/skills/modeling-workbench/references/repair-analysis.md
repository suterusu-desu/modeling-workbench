# Bounded repair analysis

Start with the exact retained question and evidence, then call `analyze_repair(case_path="/absolute/path/case.json")`. A proposed delta is optional and uses the ordered scalar controls. The operation writes local analysis records only. Use an isolated store for tests; use the current episode facade to associate an actual modeling analysis when appropriate.

Check `disposition`, diagnostic counts, and `numerical_status` together. `candidate` means the supplied local constraints passed with declared coverage; `native_ready` and appearance acceptance remain false. A `diagnostic_trial_only` prediction is a witness to failure, not a candidate to apply. Unknown bounds are omitted, not converted to zero movement. Read the returned `reads` descriptors for exact constraints, per-layer effects, nominations and numerical phases. Each call is bounded; follow its immutable next window rather than fetching the whole case blindly.

For a retained candidate, inspect the complete predicted NPZ and worst effects across all required layers, then use the established owner-controlled trial and native comparison. This analysis record does not bypass the existing proposal, state, guide/depth, checkpoint or appearance-review requirements.

Registration error bounds and layer-completeness evidence are supplied measured qualifications, not inferred from successful optimization. Control fit uses normalized phase-I linear programs, followed by an absolute-residual/control-change objective. Target rows on the same physical measurement with disjoint intervals are reported as contradictory targets. Other infeasibility interpretations are limited to the supplied local model, constraints and numerical tolerances. [SciPy's solver statuses](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linprog.html) distinguish completion, limits and numerical failure.

The operation groups repeated coordinate diagnostics only when their cause, anatomical region and physical output identities agree. It retains up to twelve nomination groups, prioritizing one per diagnostic category and then largest normalized violation/input order. Exact related subjects and diagnostic indices remain in each full nomination; coverage distinguishes groups from represented/deferred diagnostics. The compact result exposes eight nomination headers with cause, region, phase, count, next action and a thin preferred view (observation, pixel, visibility and capture requirement), plus an executable detail read. Inspect these headers before expanding large evidence records. Every diagnostic remains retained even when its nomination is deferred.

`acquisition.views` identifies `subjects`, recorded observation, visibility, and optional `new_capture_required`/`pixel_area`. Only supplied visible views are preferred; preserve stationary context, identity evidence and the new-form question. `acquisition.native_motion_baselines` holds native sampled arrays; it is separate from `video_phase`, which must identify actual generated-video/frame evidence and its reviewed native mapping or explicitly say that mapping is missing. Native sample count does not establish video continuity. Existing requests conservatively prevent nominating another generation. This selection is an evidence-based proposal, not a proof of an optimal view or authorization to spend credits.


`analyze_repair(case_path, proposed_delta=None, max_seconds=20)` retains an offline `repair_analysis` record and a compact diagnostic index. It does not contact Blender, submit generation, select artistic targets, approve appearance, or automatically create a native proposal. Historical/native freshness stays separate.

The version-1 case is JSON with `question`, `state` (source_state_id, pose, frame, units, dependency_fingerprint), `outputs` (ordered object/native_vertex/layer identities), `controls` (ordered named scalar controls with their actual coordinate/mechanism meaning), `response`, `layers`, `targets`, `preservation`, `evidence`, and optional `acquisition` context. Referenced files use `{path, sha256}`; all referenced bytes are pinned before analysis. Paths resolve relative to the case file. Exact inputs, full per-constraint results and predicted arrays remain available behind the compact result.

`response.arrays` names an NPZ containing CSR `data`, `indices`, `indptr`, `shape=(3*N,K)`, `baseline_xyz=(N,3)`, and finite `lower_delta`/`upper_delta=(K,)`. Rows are point-major XYZ; columns are named scalar controls. A column may change any output coordinate. An upstream subdivision operator is not a final ocular/lash response. `response.kind` is `exact_linear` or `local_derivative`; `response.validity_status`, `validation_evidence`, finite ranges, and the same state/domain/pose/dependency fields qualify its use. Missing response data is an explicit diagnostic, not a substituted scalar model. A local derivative never establishes finite nonlinear or whole-motion validity.

`native_baselines` contains object/frame/source_state_id and a hashed NPZ `file`, plus `xyz_key`, for independently captured reference coordinates indexed by each output's native_vertex. Compare the response baseline to these arrays before a candidate is eligible. Missing or mismatching baselines remain explicit. No coordinate-frame conversion is inferred.

Declare `required_layers` for the control scope, including unmeasured layers. Each `layers` entry declares its name, `complete_for_controls` as the complete list of control IDs, missing coverage, included outputs/proven-zero boundary, and evidence. Missing layers or unverified dependent lashes/motion block a complete candidate even when face-only predictions are useful. Sparse zeros alone never establish completeness.

Targets are named scalar linear measurements of XYZ, grouped by anatomical region. Each row has `id`, `region`, `terms` (`output`, three-component `direction`), finite `lower`/`upper`, positive `scale`, and `support` with status, exclusions, correspondence, visibility, registration status/sensitivity and evidence. `support.registration` is `{status: "qualified", error_bound: nonnegative_number}` only after a measured bound is justified. That error bound shrinks each acceptable interval; if it consumes the tolerance, alignment remains unresolved. Three coordinate rows represent a positional box, not a Euclidean sphere. A row with unknown intended bounds can omit them and remains a missing-target question. Bounds are authored/qualified targets; the tool does not invent them from a screenshot or nearest surface. Required unsupported targets cannot disappear from candidate readiness.

Preservation rows use the same linear terms and bounds, with reason/evidence and interpretation. Set `lower_unbounded` or `upper_unbounded` explicitly for a one-sided condition; a null bound alone remains unknown. These express fixed or bounded coordinates, relative attachment, and fixed-normal clearance locally. They do not prove collision-free motion, exact volume preservation or nonlinear skin continuity. All required rows are checked independently of fit quality. List nonnumeric, unresolved required relationships in `unresolved_requirements` with id/reason/region/evidence; the tool preserves them as blockers instead of inventing thresholds. `baseline_constraints` checks recorded baseline measurements separately even when no candidate can be computed.

The solver works within finite qualified control bounds. Separate fit-only, preservation-only and joint normalized phase-I checks distinguish insufficient qualified controls from incompatible stated constraints. A timed-out or numerically failed solve stays unresolved; it is never reported as infeasible. A solver conclusion concerns only this supplied local linear problem. Candidate optimization minimizes normalized absolute target residual plus a small control-change penalty under all hard bounds; every result is rechecked numerically.

Diagnostics identify the exact row, output/native region, pose, evidence and next action. Acquisition nominations distinguish target absence, uncertain registration/correspondence, control limitations, constraint conflicts and response validity. They preserve exact recorded view/phase links, stationary context, identity and existing motion evidence. Generate a new source only when its missing visible form/support is identified; higher resolution or mesh density alone is not an explanation. Nominations do not authorize dispatch. Transport input limits govern a selected request, not the complete retained evidence set.
